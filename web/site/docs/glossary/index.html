Glossary

The words used in these docs, in plain language.

WordMeaning
AI agentAn AI that runs tools by itself to finish a task, such as Claude Code, Codex, Cursor or Gemini CLI.
Approval windowThe window komando opens on your screen when an AI agent asks to run something that needs your yes. It runs only after you click Allow once. See Safety.
Audit logkomando's history of every action: who, what, where and the result. See it with komando audit.
Bastion / jump hostA gateway server you go through to reach private servers. In komando you write it as --via bastion.
BucketA folder-like container for files in object storage (S3, MinIO, R2).
CacheA fast, temporary store an app uses to speed things up, such as Redis or Valkey.
CLI / terminalA command-line interface: a window where you type commands instead of clicking.
ClusterA group of machines that run containers together, managed by Kubernetes or Docker Swarm.
Connkomando's word for anything you connect to that is not a server: a database, cache, queue, storage bucket, cluster or registry. Add one with komando conn add.
ContainerAn app packed with everything it needs, so it runs the same everywhere (Docker).
Container imageThe packed app a container starts from, such as nginx:1.27.
Container registryA server that stores container images: Docker Hub, GHCR, Harbor, ECR.
DatabaseWhere an app keeps its data in tables: PostgreSQL, MySQL, SQLite.
Dry runRunning a command with --dry-run: it shows what would happen, without changing anything.
Exit codeA program's result number: 0 means success, anything else means a problem. See Results and errors.
Fingerprint / host keyA server's ID card. If it changes, komando does not connect (HOSTKEY_MISMATCH).
FlagAn option added to a command, such as --yes or --dry-run.
GroupA named set of servers and conns, used as a target with @name (for example @web).
HostThe command word for a server: komando host add, komando host edit. Results name each target in a field called host.
JobA long task left running on a server, started with komando job start.
JSONStructured text that programs read easily. komando answers agents and scripts in JSON.
Message queueA service that passes messages from one app to another: Kafka, RabbitMQ, NATS, Amazon SQS, Google Cloud Pub/Sub. See Queues.
NamespaceA named section inside a Kubernetes cluster, used to keep apps apart.
Object storageA service that stores files as objects in buckets, reached over the internet: S3, MinIO, R2.
PodThe smallest unit Kubernetes runs: one or more containers together.
ProtectedA server, conn or VPN marked with --protected, for production. Before a change there, komando asks you; an AI agent or a script needs --yes, which a person approves. See Safety.
RecipeA ready-made or saved command, run with komando recipe run NAME TARGET.
SecretA password, token or key kept in komando's encrypted vault, referred to as secret:NAME.
Selector / targetWhat a command works on: a name, a group (@web), a tag (tag:prod), a glob (web-*), or all. See Targets.
ServerA computer (often in the cloud) that runs your apps.
ServiceA background program, such as nginx, managed by systemd (or by Windows). Managed with komando svc.
SSHThe secure way to log in to and control a Linux server remotely.
SSH keyA pair of files that proves who you are; safer than a password.
sudoRunning a command as the administrator (root).
Tag / labelA word (prod) or key=value pair (env=prod) you attach to servers and conns, so you can pick them as a target.
TunnelMakes a remote service, such as a database, appear on your own computer.
Vaultkomando's encrypted storage for passwords and other secrets.
VPNA private network link to a company or cloud network. komando can connect several at once, by itself, when a target needs one.
Your listEverything you added to komando: servers, conns and VPNs. See it with komando list.
