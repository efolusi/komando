Melindungi production

Tandai server atau conn sebagai dilindungi, dan komando bertanya sebelum setiap perubahan di sana:

komando host edit web1 --protected        # komando bertanya sebelum setiap perubahan di web1
komando conn edit prod-db --protected     # sama untuk sebuah database
komando policy check 'rm -rf /'           # apakah ini akan diblokir? (exit 6 bila ya)
komando audit -o text                     # apa yang dilakukan, dan oleh siapa

Jika diketik tanpa argumen, komando host edit menanyakan server, lalu apa yang diubah.

Saat web1 diubah nanti, komando bertanya dulu:

web1 (protected): this command changes it. Continue? [y/N]

Agen AI atau script tidak ditanya: mereka menambahkan --yes setelah seseorang setuju (lihat Saat Anda di terminal).

Sabuk pengaman

Sabuk pengamanFungsinya
Filter perintah berbahayaMemblokir perintah seperti rm -rf /, mkfs, reboot, DROP DATABASE, curl … | sh, mengosongkan firewall, dan menghentikan SSH, di server, di pod, dan di database. Lihat semuanya dengan komando policy list.
Server dan conn yang dilindungiPerubahan apa pun padanya butuh jawaban ya. Untuk entrinya sendiri itu berarti mengarahkan ulang (alamat, port, user, key, kata sandi, --via), mengganti secret yang dipakainya (key, pre-shared key, atau profil VPN yang dilindungi juga), mengganti namanya, menghapusnya, dan mematikan perlindungan; tag, grup, label, dan catatannya berubah tanpa itu. Perintah yang hanya melihat bisa menyatakannya dengan --read-only dan berjalan tanpa jawaban ya. Apa pun di alamat dan port yang sama (target user@address, nama kedua, nama yang di-resolve ke IP yang sama, conn kedua ke server database yang sama, server SSH di balik conn sftp:// yang dilindungi) juga dilindungi, VPN atau bastion mana pun yang dilaluinya. Dengan banyak target, komando memeriksa semuanya sebelum menjalankan apa pun: satu target yang dilindungi menghentikan seluruh perintah sebelum yang pertama berjalan (di terminal, komando bertanya sekali), dan kesalahan menyebut setiap target yang dilindungi. Perintah tidak pernah berhenti di tengah jalan karena perlindungan.
Read-only secara defaultdb query, cache run, dan cluster run hanya membaca kecuali ditambahkan --write. Di PostgreSQL, MySQL, Oracle, dan ClickHouse, database sendiri yang memberlakukannya (transaksi read-only, atau readonly=1 milik ClickHouse); SQL Server selalu me-rollback SQL-nya. Di Snowflake, BigQuery, dan MongoDB, pemeriksaan komando sendiri atas setiap pernyataan menjaganya tetap pembacaan: untuk jaminan yang keras, sambungkan dengan user yang hanya boleh membaca. Lihat database.
Dry run--dry-run menampilkan apa yang akan berjalan dan apakah akan diblokir (meta.would_be_blocked). Dry run sendiri tidak pernah diblokir, dengan satu pengecualian: perintah agen AI dengan KOMANDO_HOME yang diatur ke folder lain berhenti, dry run atau bukan (lihat folder data yang lazim, di bawah). Dry run tidak pernah membuka jendela persetujuan, jadi untuk agen AI --reveal tidak dihitung di dry run (output tetap disamarkan), dan pratinjau agen tersambung dengan --host-key-policy off diabaikan.
Pengaturan keamananMematikan audit log atau pemeriksaan identitas server, memindahkan key vault keluar dari keychain, menghapus aturan deny, atau agen AI mengatur --proxy-command (program di komputer ini) butuh jawaban ya.
Identitas serverBila fingerprint server berubah, komando menolak tersambung (HOSTKEY_MISMATCH).
Edit yang amanEdit file menggantikan persis teks yang disebut, menulis seluruh file sekaligus (tidak pernah setengah tertulis), dan bisa menyimpan backup .bak. Sebagai root (--sudo), komando tidak mengikuti link yang dibuat user server lain, dan tidak menulis ke folder yang bisa diubah user lain, karena user itu bisa menukar file dengan link saat root menulis (SHARED_FOLDER_CONFLICT).
Vault tersegelKata sandi disegel dengan AES-256-GCM, dengan key di keychain OS (atau, bila tidak ada, di file di samping store; komando doctor memperingatkan). Hanya nama yang pernah ditampilkan. Hanya orang yang bisa melihat nilai: di terminal, atau dari aplikasi Komando untuk Mac setelah Allow once di jendela komando (secret show --reveal, key show --reveal); agen AI tidak pernah bisa, dan setiap nilai yang ditampilkan ada di audit log (Melihat nilai lagi). secret rename dan secret cp mengganti nama dan menyalin di dalam vault, jadi nilai tidak perlu ditampilkan atau diketik lagi. secret check membiarkan orang membandingkan nilai tanpa menampilkannya. Key kode persetujuan hanya bisa diubah dengan komando config approval-code (RESERVED_SECRET). Lihat Secret.
Secret disembunyikan di outputBila secret vault muncul di apa yang dikirim balik server (file .env, baris log, env), komando mencetak [secret:NAME] sebagai gantinya, juga saat di-encode base64 atau URL. Nilai yang lebih pendek dari 6 karakter tidak disembunyikan. Agar penyembunyian ini tidak bisa memberi tahu agen AI tebakan mana yang merupakan secret, nilai vault di argumen, script, atau input milik agen sendiri tidak disembunyikan di output perintah itu, dan perintah menjawab seperti untuk nilai lain mana pun; hal itu ditulis ke audit log, tempat Anda melihat tebakannya.
RiwayatSetiap tindakan ada di komando audit (lihat di bawah).

Saat Anda di terminal

Siapa yang ditanya bergantung pada siapa yang menjalankan perintah:

  • Anda, di terminal: komando bertanya kepada Anda dulu, dan menjalankan perintah hanya setelah jawaban Anda.
  • Agen AI atau script: komando tidak pernah bertanya. Perintah berhenti dengan exit 6 dan sebuah kode (PROTECTED_TARGET, POLICY_BLOCKED ...), dan hint menyebut flag yang dibutuhkan eksekusi sungguhan: --yes, atau --allow-dangerous untuk langkah yang tidak bisa dibatalkan. Agen atau script menambahkan flag itu setelah seseorang setuju.
  • Agen AI yang menambahkan flag: komando membuka jendela "Allow once" di layar, dan perintah berjalan hanya saat Anda mengkliknya (lihat Sabuk pengaman untuk agen AI). Flag milik script dihitung apa adanya.
  • Job CI (CI diatur) tidak pernah dianggap orang, bahkan di terminal: tidak ada yang ditanyakan di sana.

Di terminal komando bertanya dengan salah satu dari tiga cara:

  • Perubahan pada server, conn, atau VPN yang dilindungi: web1 (protected): this command changes it. Continue? [y/N].
  • Langkah yang tidak bisa dibatalkan: This <what it does>., dan Anda mengetik nama apa yang akan hilang: key, file, secret, topic, atau image bila satu yang hilang (Type the name session:42 to continue), jumlahnya bila beberapa yang hilang (Type 37 (objects under daily/ in backups) to continue), atau nama server atau conn untuk langkah pada seluruh target (reboot, restore, perintah yang diblokir filter). Tidak pernah kata yes. Pada target yang dilindungi, pertanyaan yang sama menyatakannya, dan jawaban Anda mencakup perlindungan juga: komando bertanya sekali.
  • Perubahan yang mematikan salah satu pemeriksaan komando sendiri (config set audit off, host_key_policy off, menghapus aturan deny, kembali ke komando yang lebih lama): This turns off a komando safety check: <what>. Continue? [y/N].

Lebih lanjut tentang pertanyaannya:

  • --proxy-command atau program login cluster yang cocok dengan sebuah aturan menyatakan Blocked by policy: ... dan meminta Anda mengetik nama server atau conn untuk tetap menjalankannya, sekali ini saja.
  • Saat komando menanyakan argumen yang kurang kepada Anda, komando bertanya Run it? [y/N, d = --dry-run first] sebelum perintah berjalan. Perintah yang tidak bisa dibatalkan (menghapus data atau file, reboot, menghentikan sshd, sync --delete) lalu meminta Anda mengetik nama apa yang akan hilang, sekali. cron rm, pkg rm, dan db kill tidak butuh apa-apa lagi dari agen AI, tetapi Anda mengetik nama apa yang akan hilang sebagai ganti menjawab Run it?. Satu tabel aturan menentukan yang mana: setiap perintah yang menghentikan agen AI sebagai berbahaya meminta nama kepada Anda.
  • Tidak adalah default; Enter atau Ctrl-D berarti tidak, dan tidak ada yang berjalan. Jawaban tidak keluar dengan 6, seperti penghentian: Cancelled. Nothing was changed. (DECLINED saat komando bertanya sebelum perintah berjalan, kalau tidak kode penghentian itu sendiri). Ctrl-C menghentikan komando di sana: Stopped., exit 1 (CANCELLED).
  • Jawaban ya hanya berlaku untuk satu perintah itu, seperti --yes atau --allow-dangerous, dan komando audit mencatatnya dengan confirm: tty dan apa yang Anda jawab ya.
  • Sebagian penghentian tidak punya flag dan tidak pernah ditanyakan: HOSTKEY_MISMATCH, NEEDS_PERSON, SSH_GATE_NETWORK_REQUIRED, SSH_GATE_READ_ONLY, SSH_GATE_REFUSED, STORE_OLD_COPY, dan REVEAL_NEEDS_TERMINAL. Hanya orang yang menjalankan perintah itu, di terminalnya sendiri.

Setiap penghentian yang bisa diangkat sebuah flag punya hint yang sama, menyebut setiap flag yang dibutuhkan eksekusi sungguhan: agen AI membaca check with --dry-run, ask the user; once they agree, run it again with --yes, script mendapat baris perintahnya sendiri dengan flag yang sudah terisi.

Sabuk pengaman untuk agen AI

komando mengenali Claude Code, Codex, Gemini CLI, dan Cursor dari variabel lingkungan yang mereka atur (variabel yang ada dihitung, apa pun nilainya, juga 0 atau kosong), dan menambahkan aturan ini untuk mereka. Untuk agen lain, atur KOMANDO_AGENT=1 (atau AI_AGENT=1) di lingkungan tempat agen menjalankan perintah, supaya aturan ini berlaku juga untuknya. Script dan Anda di terminal tidak terpengaruh olehnya.

Sabuk pengamanFungsinya
Seseorang mengizinkan flag berisikoSaat agen menambahkan --yes, --allow-dangerous, atau --reveal, komando membuka jendela di layar dengan seluruh perintah, alasan komando menghentikannya (aturan yang cocok, server yang dilindungi), server tempat perintah berjalan dan, bila baris perintah tidak menunjukkannya, program di komputer ini yang diizinkannya berjalan. Untuk exec --script FILE, job start --script FILE, dan exec --stdin-file FILE, jendela juga menampilkan SHA-256 file dan setiap barisnya, tidak pernah sebagian: file yang lebih panjang dari 40 baris (baris panjang dibungkus di 100 karakter) atau 16 KB, yang bukan teks valid atau memuat karakter bidi atau zero-width, dan yang tampak memuat kata sandi, key, atau token tidak mendapat jendela, dan agen meminta Anda menjalankan perintahnya sendiri. SQL dari db query --file ditampilkan dengan cara yang sama, begitu juga perintah yang diisi recipe (recipe run), dengan catatan bila berjalan dengan sudo: recipe tersimpan bisa diganti di antara dua eksekusi, jadi Anda mengizinkan apa yang berjalan, bukan sebuah nama. Isi yang disimpan atau dikirim perintah dari file atau dari stdin (fs write --from, cluster apply --file, queue send --from, unggahan dengan cp, upload, atau storage upload, file -f dan --from-file milik cluster run, arsip pg_dump untuk db restore) ditampilkan utuh bila muat. File bernama yang hanya terlalu panjang, atau bukan teks (arsip, gambar), disebut dengan ukuran dan SHA-256-nya, dengan catatan bahwa isinya tidak ditampilkan, sehingga file itu bisa diperiksa lebih dulu; isi di stdin yang terlalu panjang, dan isi yang memuat karakter tak terlihat atau tampak memuat kata sandi, tidak mendapat jendela. Folder (cp -r, sync) ditampilkan sebagai daftar file-nya, masing-masing dengan ukuran dan SHA-256; daftar yang lebih panjang dari 40 baris tidak mendapat jendela. SQL polos dari db restore adalah kode, seperti db query --file: ditampilkan utuh (.gz dibuka) atau tanpa jendela. Indentasi lebih dari 16 spasi disebut sebagai (+N), sehingga YAML yang dalam mempertahankan struktur bersarangnya. import memeriksa secret yang akan digantikannya dengan cara yang sama seperti secret set. Jawaban ya Anda mencakup apa yang ditampilkan jendela itu: bila pemeriksaan berikutnya atas perintah yang sama membawa script, aturan, atau target yang dilindungi yang tidak ada di jendela, komando bertanya lagi, dengan itu di jendela. Jawaban ya untuk --reveal dan jawaban ya untuk --yes atau --allow-dangerous tidak pernah menjawab untuk satu sama lain. Perubahan yang merusak pada target yang dilindungi bertanya sekali, di jendela yang menyebut kedua flag. Perintah berjalan hanya saat Anda mengklik Allow once. Pindah baris, tab, karakter kontrol, deretan spasi yang panjang, dan karakter yang tidak menggambar apa pun tampil sebagai escape ($'a:\n b: 1', \u3164), yang dibaca shell kembali sebagai teks yang sama. Perintah yang tidak bisa ditampilkan utuh (lebih panjang dari 500 karakter, teks tidak valid, atau dengan karakter bidi atau zero-width) tidak mendapat jendela: agen diberi tahu untuk memperpendeknya atau meminta Anda menjalankannya. Agen tidak bisa mengkliknya. Dengan komando config approval-code, jendela juga meminta kode 6 digit dari aplikasi authenticator, jadi satu klik saja tidak cukup (lihat Pengaturan). Di desktop Linux atau BSD (X11 atau Wayland), tempat program lain bisa menekan tombol jendela, kodenya wajib: tanpanya komando tidak membuka jendela, dan agen meminta Anda menyalakan kode atau menjalankan perintahnya sendiri (macOS dan Windows mempertahankan jendela biasa). Tanpa layar (sesi SSH, server, KOMANDO_NO_DIALOG diatur), agen ditolak dan meminta Anda menjalankan perintah di terminal Anda sendiri. Jendela yang tidak dijawab siapa pun menutup setelah 2 menit; agen diberi tahu tidak ada yang menjawab (bukan bahwa Anda mengklik Deny) dan bertanya kepada Anda apakah mau mencoba lagi.
Secret disembunyikan dari agenKata sandi, key, dan token di output apa pun (file .env, env, baris log, baris database, Kubernetes Secret, requirepass di redis.conf, private key, hash kata sandi) tampil sebagai [hidden]. Anda dan script melihat nilai sebenarnya.
Data pribadi disembunyikan dari agenDi server dan conn yang dilindungi, alamat email, nomor telepon, nomor kartu, dan IBAN di apa yang dibaca agen (baris database, nilai cache, baris log, file) tampil sebagai [hidden: email], [hidden: phone], [hidden: card], dan [hidden: iban]. Lihat Data pribadi.
Agen tetap bisa mengatur secretfs replace --old 'DB_PASSWORD=[hidden]' --new 'DB_PASSWORD={{secret:db}}' --yes menaruh nilai vault di server tanpa dilihat agen, setelah Anda mengizinkannya di jendela. Teks yang masih memuat [hidden] tidak pernah ditulis menimpa file asli (HIDDEN_VALUE). Agen bisa mengganti nama secret dengan secret rename (setiap rujukan ikut) tanpa melihatnya.
Seseorang menentukan ke mana secret pergiBegitu sebuah nilai ada di server yang dikendalikan agen, nilai itu bisa kembali dalam bentuk yang tidak dikenali komando (dibalik, dalam heksadesimal, dipotong-potong). Jadi saat agen mengirim secret ke suatu tempat, agen butuh --yes, dan jendela menyebut secret dan tempatnya (SECRET_DESTINATION): {{secret:NAME}} di fs write dan fs replace, exec --env K=secret:NAME dan job start --env, db user add dan db user passwd, dan rujukan kata sandi atau pre-shared key (secret:, env:, file:, ...) yang dipasang host add, host edit, conn add, conn edit, vpn add, vpn edit, atau impor pada server, conn, atau VPN, atau server, conn, atau VPN dengan rujukan yang pindah ke alamat, port, server VPN, jalur --via, atau proxy command lain. Memindahkan jump server dihitung untuk semua yang ada di belakangnya: agen yang memberi server alamat, port, --via, atau proxy command baru ditanya tentang setiap kata sandi yang dikirim server dan conn lain melaluinya. Memindahkan VPN dihitung dengan cara yang sama: vpn edit agen pada alamat, portal, server, atau profilnya, vpn add --overwrite, impor yang menggantikannya, atau profil baru di vault, ditanyakan untuk setiap kata sandi tersimpan yang dikirim server dan conn lewat VPN itu (jalur --via mereka lewat VPN, termasuk jump server); server yang hanya memakai key tidak mengirim apa pun. Begitu juga secret yang menentukan siapa yang dipercaya komando: agen yang mengganti profil VPN OpenVPN di vault (secret set, secret cp --overwrite, secret rename --overwrite) ditanya seperti untuk vpn edit (jendela menyebut server barunya), dan yang mengganti, atau membuat, sertifikat CA tempat server WinRM atau conn diperiksa (?ca=secret:NAME), atau mengarahkan server WinRM ke server lain, juga butuh jawaban ya dari Anda (SAFETY_SETTING). Edit yang mempertahankan tempatnya (tag, nama user) tidak menanyakan apa pun. Nilai env milik server sendiri dari vault (host edit --env KEY=secret:NAME) dikeluarkan dari perintah agen, dengan peringatan pada exec dan job start, kecuali agen menambahkan --yes dan Anda mengizinkannya. Dry run tidak pernah bertanya: dry run mempertahankan {{secret:NAME}} apa adanya dan menyatakan apa yang dibutuhkan eksekusi sungguhan.
Seseorang menentukan soal koneksi yang lebih lemahAgen yang menambah conn yang URL-nya menurunkan perlindungan jaringan, atau mengeditnya sehingga demikian, butuh --yes dan jawaban ya Anda di jendela (SAFETY_SETTING): sslmode=disable, allow, atau prefer (PostgreSQL), tls=false, preferred, atau skip-verify (MySQL), encrypt=false, encrypt=disable, atau tls=skip-verify (SQL Server), tls=false atau tls=skip-verify (Oracle, ClickHouse, registry, FTPS), tls=skip-verify atau insecure=1 (Kafka, RabbitMQ, NATS, SQS, Pub/Sub), insecure=1 (FTP, Redis, memcached), endpoint http:// (BigQuery), dan berpindah dari rediss://, memcacheds://, atau endpoint https ke yang tanpa TLS.
Folder data yang lazimKOMANDO_HOME memindahkan data komando. Di folder baru komando tidak mengenal satu pun server yang dilindungi, aturan deny, atau host key yang di-pin, dan akan menulis audit log di sana. Jadi perintah agen dengan KOMANDO_HOME selain ~/.komando berhenti (NEEDS_PERSON), dry run juga: pratinjau di folder lain tetap akan tersambung, tanpa host key yang di-pin, dan tidak memperlihatkan apa pun yang nyata. Tidak ada flag atau jendela yang meloloskannya, karena kode persetujuan yang mungkin dinyalakan disimpan di folder lazim, bukan di folder itu. komando tidak membuat dan tidak menulis apa pun di folder lain itu, jadi penghentian ini tidak ada di audit log mana pun. Agen diberi tahu untuk menghapus KOMANDO_HOME dan menjalankan perintah lagi, yang lalu memakai folder sendiri. komando guide uninstall, yang mencabut guard agen, berhenti dengan cara yang sama. Bila data komando disimpan di tempat lain, jadikan ~/.komando sebuah link ke folder itu: link ke folder yang sama dihitung sebagai ~/.komando. HOME tidak memindahkannya untuk agen: komando mengambil folder home agen dari database user komputer, jadi HOME=/tmp/x komando ... tetap memakai ~/.komando (dan guard menolak baris itu). Mengatur keduanya, HOME=/tmp/x KOMANDO_HOME=/tmp/x/.komando, adalah folder lain seperti KOMANDO_HOME mana pun: berhenti. Anda, di terminal Anda sendiri, boleh mengatur HOME, dan komando mengikutinya. Akun yang tidak dikenal database user (di Linux komando juga bertanya ke getent, jadi akun LDAP dan sssd dihitung) tidak memberi komando apa pun untuk memeriksa HOME: perintah agen lalu butuh jawaban ya Anda di jendela (SAFETY_SETTING).
Tanpa menebak secretsecret check, yang menyatakan apakah sebuah nilai adalah yang tersimpan, hanya untuk orang (NEEDS_PERSON): untuk agen, perintah itu akan menjawab ya atau tidak atas tebakan. secret show hanya memberi tahu agen apakah nilai diawali atau diakhiri spasi, tidak pernah panjang atau hash-nya (hash kata sandi pendek bisa ditebak secara offline).
File secret tetap di serverAgen tidak bisa menyalin file yang merupakan secret menurut namanya (.env, private key, credentials, shadow, ...) ke komputer ini (SENSITIVE_FILE); salinan folder mengeluarkannya. Agen bisa membacanya dengan fs cat, disamarkan. Aliran ke stdout (--to -) mempertahankan aturan yang sama sebelum satu byte pun ditulis: teks dengan nilai secret sebagai [hidden], file biner ditolak bila memuat nilai vault, secret, atau data pribadi yang disembunyikan komando, dan apa pun di atas 16 MB ditolak, karena byte di stdout tidak bisa ditarik kembali. File teks lain yang diunduh agen (download, sync, storage download) disimpan seperti yang ditampilkan fs cat, dengan nilai secret sebagai [hidden], dan hasilnya menyatakan masked; salinan seperti itu tidak pernah diunggah kembali (HIDDEN_VALUE). File biner dan file di atas 16 MB disalin apa adanya, kecuali memuat nilai vault, atau target menyembunyikan data pribadi dari agen (lihat Data pribadi).
File secret tetap di komputer iniUntuk agen, komando tidak membaca ~/.komando, private key, credential store, atau file yang merupakan secret menurut namanya saat perintah menerima file lokal (--stdin-file, script FILE, unggahan, sync, fs write --from, db --file, cluster -f) (SENSITIVE_FILE); unggahan folder dan sync memeriksa setiap file dan mengeluarkan yang itu. Itu berlaku untuk file yang sama dengan nama lain: link, hard link, atau huruf besar dan kecil yang berbeda di macOS. Anda mengizinkan secret proyek seperti .env dengan --reveal; data komando sendiri dan /proc/PID/environ tidak pernah ikut. Impor (komando import kubeconfig, pgpass, docker, ...) boleh membaca file kredensial, karena memasukkan secret ke vault komando, yang tidak pernah dilihat agen. Rujukan kata sandi file: atau env: juga tidak bisa menunjuk ke data komando, private key, credential store, atau kata sandi secret store. Tidak ada rujukan, untuk siapa pun, yang membaca key kode persetujuan (RESERVED_SECRET). Perintah agen juga tidak menulis ke sana: download, cp, sync (dan --delete-nya), storage download, db dump --to, export --to, dan cluster cp tidak pernah menyimpan file ke folder komando, ~/.ssh, ~/.aws, ~/.config/gcloud, ~/.azure, ~/.kube, ~/.docker, ~/.gnupg, ~/.password-store, atau keychain, juga lewat link (SENSITIVE_FILE, tanpa flag: Anda menjalankan perintah seperti itu di terminal Anda sendiri).
Guard di komputer inikomando guide install menambahkan guard ke Claude Code, dan ke Cursor, Gemini CLI, dan Codex di tempat agen itu dipakai. Sebelum agen membaca file atau menjalankan perintah shell, komando memeriksanya dan menghentikan pembacaan ~/.komando, private key, file .env, dan credential store (~/.kube, ~/.aws, keychain), mendaftar semua variabel lingkungan, mengubah atau mengosongkan variabel yang dipakai komando untuk mengenali agen (CLAUDECODE=0, unset, env -u, env -i, read, sudo komando) atau KOMANDO_HOME, mengatur HOME di depan komando, mencari atau mengarsipkan folder yang memuatnya (grep -r ~, tar -C ~ ...), dan menjalankan ssh/scp di sekitar komando. Guard membaca path relatif dari folder kerja agen, mengikuti cd, dan menghitung glob seperti ~/.komand?/* sebagai path yang mungkin dicocokkannya; pola yang dikutip (grep '.*' f) bukan glob. Lewati dengan --no-guard.

Menambah aturan sendiri

komando policy deny 'terraform\s+destroy'           # regular expression Go; mencetak id-nya
komando policy list                                  # aturan bawaan dan aturan deny Anda, dengan id
komando policy rm 'terraform\s+destroy'              # hapus lagi
komando policy rm custom-1a2b3c4d                    # atau hapus menurut id-nya
komando policy check 'terraform destroy'             # exit 6 bila akan diblokir
komando policy check --conn-kind postgres 'delete from users'   # nilai SQL, Redis, atau MongoDB sebagai gantinya

Aturan mencocokkan perintah seperti shell membacanya, jadi tanda kutip dan backslash di dalam sebuah kata (r\m, /e""tc) tidak menyembunyikannya. Pola kustom yang bukan regular expression valid memblokir setiap perintah sampai diperbaiki atau dihapus; komando doctor dan policy list menyebutnya.

Aturan bawaan tidak bisa dihapus. Id aturan kustom (custom- dan delapan huruf dan angka) dibuat dari polanya, jadi tetap sama saat aturan lain dihapus. Pola yang cocok dengan teks kosong (.*) ditolak: pola itu akan memblokir setiap perintah. Menghapus aturan mematikan sebuah pemeriksaan, jadi komando bertanya dulu (script menambahkan --yes).

policy check keluar dengan 6 bila perintah akan diblokir, jadi bisa dipakai di if. --conn-kind menilai sebuah pernyataan untuk jenis conn sebagai gantinya: postgres, mysql, sqlserver, oracle, clickhouse, snowflake, bigquery, sqlite, redis, memcached, atau mongodb (dokumen perintah sebagai JSON). Perintah ini juga keluar dengan 6 bila pernyataan bersifat merusak, yang ditolak db query dan cache run tanpa --allow-dangerous.

Data pribadi

Data pelanggan di production tidak boleh sampai ke model AI. Di server dan conn yang dilindungi, agen AI melihat data pribadi disembunyikan di apa yang dibacanya dari sana: baris db query (juga dengan -o csv), cache get dan cache run, storage cat, fs cat, exec, logs, dan perintah lain yang menampilkan data dari server atau resource. Inventaris komando sendiri (alamat server, URL conn) tidak pernah disembunyikan.

komando conn edit prod-db --option 'mask_columns=name address birth_date'

  • Pengaturan mask_personal adalah protected (default), all, atau off. Menampilkan lebih banyak kepada agen (all ke protected, atau off) mematikan sebuah pemeriksaan, jadi komando bertanya dulu; script menambahkan --yes.
  • Nama dan alamat jalan tidak punya bentuk yang bisa ditemukan komando, jadi sebut kolom yang memuatnya di mask_columns, dipisah spasi. Mengaturnya juga menyalakan penyembunyian data pribadi untuk conn itu.
  • Query yang menyebut kolom tersembunyi bisa mengganti namanya (name AS customer), menghitung darinya (upper(name)), atau menanyakannya (WHERE name LIKE 'A%'), dan komando tidak bisa membedakan hasil mana yang berasal darinya. Jadi db query agen AI yang menyebutnya di mana pun berhenti dengan REVEAL_NEEDS_PERSON (exit 6): seseorang mengizinkannya dengan --reveal. SELECT * menampilkan kolom itu sebagai [hidden: column] di samping yang lain. Di MongoDB namanya adalah field, disembunyikan di kedalaman berapa pun, dan perintah yang menyebut salah satunya berhenti dengan cara yang sama.
  • Ini menghentikan query biasa, bukan database yang menyusun nama saat berjalan (nilai seluruh baris, SQL dinamis, view yang mengganti nama kolom). Untuk kolom yang tidak boleh dibaca agen, jangan beri user database conn itu hak untuk membacanya.
  • Data yang sama tidak diserahkan lewat jalan lain. Untuk agen AI, di tempat data pribadi disembunyikan: cp, sync, dan download menyimpan file dengan data itu disembunyikan; fs replace, fs write --dry-run, fs restore, dan docker compose menampilkannya tersembunyi; db dump berhenti dengan SENSITIVE_FILE (dump tidak bisa disamarkan). Nilai yang bukan teks ditampilkan sebagai base64; bila memuat secret atau data pribadi, seluruh nilai terbaca [hidden].
  • File yang tidak bisa ditampilkan komando dengan data pribadi disembunyikan menghentikan cp, sync, download, atau cluster cp milik agen AI dengan SENSITIVE_FILE: file biner yang teksnya memuat secret atau data pribadi, file biner di atas 256 KiB (terlalu besar untuk diperiksa), dan file apa pun di atas 16 MiB. Seseorang mengizinkannya dengan --reveal.
  • Penyembunyian mengikuti database, bukan nama conn: conn kedua ke database yang sama (alamat server dan nama database yang sama) menyembunyikan sama banyaknya. Conn ke server yang sama dengan alamat lain (nama host sebagai ganti IP, port localhost milik tunnel) tidak dikenali sebagai yang sama, begitu juga file SQLite dengan path lain (~/app.db dan path lengkapnya, link, huruf besar dan kecil lain di macOS). Di PostgreSQL penyembunyian berlaku per database; di MySQL, SQL Server, ClickHouse, MongoDB, dan yang lain, yang conn-nya membaca setiap database di server, penyembunyian mencakup seluruh server.
  • Mengeluarkan kolom dari mask_columns, mematikan mask_personal, atau menggantikan (conn add --overwrite, import --overwrite) atau menghapus conn seperti itu menampilkan lebih banyak kepada agen: agen AI butuh jawaban ya dari seseorang untuk itu (SAFETY_SETTING), seperti untuk pengaturannya. mask_columns menerima nama kolom tanpa tabel, dan opsinya ditulis dalam huruf kecil.
  • Seseorang menentukan kapan agen melihat nilai sebenarnya: dengan --reveal, yang diizinkan seseorang di jendela persetujuan, agen melihatnya untuk satu perintah itu.
  • Nilai yang disamarkan tidak pernah ditulis kembali: db query --write, cache set atau cache run --write, dan penulisan file, yang masih memuat [hidden: ...] berhenti dengan HIDDEN_VALUE.

Riwayat

Setiap tindakan ada di audit log: waktu, siapa yang menjalankan, agen AI mana yang meminta, apakah seseorang mengizinkan, target, dan perintahnya. Setiap perubahan pada inventaris dan pengaturan keamanan juga ada di sana: server, conn, grup, key, secret (hanya nama), config set (nilai lama dan baru), serta policy deny dan policy rm.

komando audit -o text                 # satu baris per entri, 50 terbaru
komando audit -n 0                    # semua entri
komando audit --failed                # hanya tindakan yang gagal atau diblokir
komando audit --target @web           # hanya server atau conn ini
komando audit --command exec          # hanya satu keluarga perintah
komando audit --since 2h              # semua dalam dua jam terakhir
komando audit --since yesterday --until today   # semua kemarin
komando audit verify                  # periksa rantainya

Setiap record membawa hash record sebelumnya, jadi komando audit verify (dan komando doctor) mengetahui record yang diedit, ditambahkan, atau dihapus di luar komando. Bila audit log tidak bisa ditulis, komando menolak berjalan (AUDIT_UNAVAILABLE). Atur KOMANDO_ACTOR untuk memilih nama yang dicatat untuk Anda atau agen. Lingkungan agen bisa mengatur nama itu menjadi apa pun, jadi record-nya menyimpan agen itu sendiri (agent) dan akun komputer ini, dibaca dari sistem (os_user), dan menandai nama itu sebagai yang diklaimnya (actor_claimed); komando audit -o text menampilkannya sebagai Claude Code (as claude). Untuk menjauhkan teks SQL dari riwayat, lihat audit_sql di Pengaturan.

Key yang hanya menjalankan komando

Untuk menjangkau komando di komputer ini dari perangkat lain (aplikasi Komando di ponsel, komputer lain), beri SSH key perangkat itu hanya komando: komando ssh-gate line mencetak baris untuk ~/.ssh/authorized_keys.

komando ssh-gate line --name phone ~/phone.pub                  # boleh membaca dan mengubah
komando ssh-gate line --name phone-read --read-only ~/phone.pub  # hanya membaca, tanpa jaringan
komando ssh-gate line --name phone-net --read-only --network ~/phone.pub  # membaca, pemeriksaan jaringan juga

Key menanyakan komando ssh-gate status yang mana ia: ssh-gate menjawabnya sendiri, dengan nama key, read_only, dan network.

Baris diawali restrict,command="/full/path/komando ssh-gate --name phone". Tambahkan ke ~/.ssh/authorized_keys milik akun tempat komando berjalan, sebagai ganti baris biasa key itu. restrict mematikan port, agent, dan X11 forwarding serta terminal (OpenSSH 7.2 atau lebih baru). Untuk key itu, sshd lalu menjalankan komando ssh-gate apa pun yang diminta key, dan:

Perubahan pada target yang tidak bisa ditemukan gate ditolak; pembacaan berjalan, kecuali namanya localhost, alamat loopback, atau alamat komputer ini sendiri, seperti ditulis atau seperti nama di-resolve (cert check https://localhost, https://ip6-localhost, nama publik yang menunjuk ke 127.0.0.1). Apa yang dihubungi pembacaan seperti itu diperiksa lagi saat tersambung, jadi nama yang jawabannya berubah di antaranya juga tidak bisa menjangkau komputer ini. Perubahan yang ditambahkan komando nanti ditolak sampai diketahui hanya bekerja pada server. Tidak ada key yang membuat komando membaca file di sini juga: exec dan job start dengan --script FILE atau --stdin-file FILE, db query --file, db restore --from, cluster apply --file, fs write --from, upload, storage upload, cp, dan sync dari path di sini, serta cluster run -- apply -f, --from-file, atau cp ke pod ditolak (SSH_GATE_REFUSED): file itu bisa berupa private key, dan jawaban server akan menyerahkannya kembali. Kirim isinya lewat input key sendiri sebagai gantinya (--script -).
Key read-onlyDengan --read-only, key hanya menjalankan perintah yang dihitung komando sebagai pembacaan (kind di komando schema): exec (juga dengan --script), job start, docker exec, dan cluster exec butuh --read-only, db query, cache run, dan cluster run tanpa --write, db explain tanpa --analyze, pkg upgradable tanpa --refresh, pkg security tanpa --refresh, dan recipe wajib ditandai read-only. storage link dan cluster forward adalah perubahan (kind: change), karena memberikan akses atau membuka port di sini: key read-only ditolak untuk keduanya (SSH_GATE_READ_ONLY), key penuh menjalankannya.
Key baca tidak menjangkau jaringanMenjangkau jaringan bukan penulisan, tetapi itu jalan keluar: apa yang dibaca key bisa keluar dalam URL atau nama DNS. Jadi key --read-only hanya menjalankan pembacaan komando sendiri atas server dan conn di daftar (fs, logs, facts, status, svc, docker ps, db query, cache run, cluster run, cert check SERVER, ...). Key itu ditolak untuk setiap perintah net, cert check pada situs web (https://HOST, HOST:PORT, yang dihubungi komando dari komputer ini), dan exec, job start, docker exec, cluster exec, dan recipe run, yang programnya (curl, nslookup, ...) bisa tersambung ke mana saja (SSH_GATE_NETWORK_REQUIRED). Pembacaan yang ditambahkan komando nanti ditolak sampai diketahui tetap pada target yang terdaftar. Perintah SQL dan cache yang menjangkau server lain atau program adalah penulisan, jadi db query dan cache run menolaknya tanpa --write: Postgres COPY ... TO PROGRAM dan dblink, MySQL INTO OUTFILE, LOAD DATA, dan LOAD_FILE, SQL Server OPENROWSET, OPENQUERY, nama linked-server (lnk.db.dbo.t) dan fungsi yang membaca path file (\\HOST\share), ClickHouse url(), remote(), dan s3(), Oracle UTL_HTTP dan XML yang disusun query (DTD bisa menyebut URL), BigQuery EXTERNAL_QUERY, MongoDB $out dan $merge, Redis MIGRATE dan REPLICAOF. Tambahkan --network ke baris untuk key baca yang boleh menjalankannya.
Setiap perintah ada di riwayatSetiap perintah yang dijalankan atau ditolak untuk sebuah key ada di komando audit: nama key (ssh_gate), apa yang dikirimnya (ssh_command, nilai yang tampak seperti secret disembunyikan), alamat asalnya (client) dan, bila ditolak, alasannya. Apa yang lalu diubah perintah itu dicatat sebagai dari ssh-gate key NAME. Catatan ini ditulis bahkan saat pengaturan audit mati; bila tidak bisa ditulis, tidak ada yang berjalan. Di teks komando audit, pindah baris dan escape terminal di apa yang dikirim key tampil sebagai \n dan \x1b, jadi key tidak bisa menambah atau menyembunyikan baris.

Beri setiap perangkat key dan nama tersendiri, sehingga komando audit membedakannya dan satu baris bisa dihapus untuk mengunci satu perangkat. Key menjangkau komando sebagai akun yang dipakainya login: pakai akun itu untuk komando saja, atau yang hanya punya izin yang dibutuhkan komando.

Batasan

Agen AI berjalan sebagai user Anda sendiri di komputer ini. Jendela persetujuan, penyamaran, dan guard menghentikan kesalahan dan prompt injection (halaman web atau file yang menyuruh agen membocorkan sesuatu). Semuanya tidak menghentikan program yang sengaja menyembunyikan jati dirinya atau mengedit guard hingga hilang: tidak ada yang berjalan sebagai Anda yang bisa. Guard membaca baris shell sebagai teks; script yang menyusun path dari potongan, atau memulai komando tanpa variabel agen dari bahasa lain, lolos darinya. Jadi:

  • beri komando, dan dengan begitu agen, user SSH yang hanya punya izin yang dibutuhkannya;
  • tandai production dengan komando host edit NAME --protected;
  • simpan key vault di keychain OS (pindahkan key dari store.key ke sana dengan komando secret keychain), sehingga orang lain atau backup yang menjangkau ~/.komando tidak bisa membuka vault;
  • beri SSH key perangkat lain hanya komando, dengan komando ssh-gate line.

Batasan lain:

  • Filter perintah berbahaya menangkap kecelakaan yang umum; ini bukan batas keamanan yang lengkap.
  • Penyamaran adalah upaya terbaik: secret dengan nama yang tidak lazim, atau lebih pendek dari teks di sekitarnya, tetap bisa lolos. Nilai yang lebih pendek dari 6 karakter tidak disembunyikan.
  • Penyembunyian data pribadi juga upaya terbaik: nomor telepon yang ditulis tanpa +, atau data pribadi di gambar atau file biner, tidak ditemukan. Sembunyikan seluruh kolom di tempat yang penting.
  • ssh-gate hanya melihat alamat yang disimpan komando untuk sebuah target (dan, untuk conn Kubernetes, URL conn, bukan server di kubeconfig tersimpannya). Key tidak bisa menyebut target sendiri: u@HOST atau IP yang tidak ada di daftar ditolak (SSH_GATE_REFUSED), karena bisa jadi alamat komputer ini sendiri. Server terdaftar di salah satu alamat jaringan komputer ini (IP LAN-nya), atau yang host key-nya yang di-pin adalah host key SSH komputer ini sendiri (/etc/ssh/ssh_host_*_key.pub: nama DNS, IP publik, atau port forward yang mengarah kembali ke sini), ditolak seperti localhost. Apa yang tetap tidak bisa dibedakan komando: conn atau cluster yang mengarah kembali ke sini dengan nama lain, dan server di sini yang belum punya key yang di-pin atau menjalankan server SSH sendiri dengan key lain. Lewat target seperti itu key mana pun, read-only juga, akan membaca file atau mendapat shell di sini (exec THAT-HOST --read-only -- 'nc -e /bin/sh ...'). Jangan daftarkan komputer ini di komando dengan cara itu: --read-only tidak membuatnya aman.
  • Key baca tanpa --network tetap menjangkau apa yang dijangkau server dan database dengan pengaturannya sendiri: foreign table Postgres, tabel FEDERATED MySQL, cluster() atau dictionary ClickHouse, external function atau stage Snowflake, remote function BigQuery di project conn sendiri, webhook API server Kubernetes. Semuanya menuju tempat yang diatur seseorang, bukan tempat yang disebut key, tetapi key yang bisa membaca lewat semuanya itu mengirim query-nya ke sana juga. Dan komando membaca SQL sebagai teks: path jaringan SQL Server yang disusun dari potongan (CHAR(92)+CHAR(92)+...) dan diteruskan ke fungsi yang tidak didaftarkan komando tidak dikenali.
  • Secret tidak pernah diterima sebagai argumen perintah, karena akan masuk ke riwayat shell (SECRET_IN_ARGS). komando secret set NAME menanyakan nilai setelah prompt muncul; lihat Secret.

Pemecahan masalah

Di terminal, komando bertanya dulu; agen AI atau script menambahkan --yes (atau --allow-dangerous) setelah seseorang setuju. Kode di bawah adalah yang diterima agen atau script.
