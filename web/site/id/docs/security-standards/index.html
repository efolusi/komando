Standar keamanan

Seberapa jauh komando memenuhi standar keamanan internasional yang cocok untuk tool DevOps yang menyimpan kredensial dan dijalankan oleh agen AI. · Keamanan

Di halaman ini

  • Periksa sendiri
  • OWASP ASVS 4.0.3 (Application Security Verification Standard)
  • OWASP Top 10 for LLM Applications (2025)
  • NIST
  • ISO/IEC 27001:2022 Annex A dan CIS Controls v8
  • Supply chain: OpenSSF Scorecard dan SLSA
  • Batasan

Ini adalah penilaian mandiri, dicek terhadap kode dan test. Ini bukan sertifikat: sertifikat (ISO 27001, SOC 2) diberikan kepada sebuah organisasi atas cara kerjanya, dan komando hanya bisa memberi kontrol untuk dipakai di sana.

Kolom status berisi terpenuhi, sebagian terpenuhi (dengan celah yang disebutkan), atau tugas Anda (langkah yang hanya bisa Anda ambil).

Periksa sendiri

komando doctor          # keamanan: izin, vault, rantai audit, conn tanpa enkripsi
komando audit verify    # tidak ada yang mengubah audit log
make lint security      # staticcheck, govulncheck (jalankan di salinan source code)
make fuzz               # fuzz parser yang membaca teks tak tepercaya

OWASP ASVS 4.0.3 (Application Security Verification Standard)

PersyaratanCara komando memenuhinyaStatus
2.10, 6.4 Secret tidak ada di kode, argumen, atau riwayatVault, rujukan secret:NAME, manager eksternal (HashiCorp Vault/OpenBao, AWS dan Google Secret Manager, Azure Key Vault, Bitwarden, KeePass, 1Password Connect); nilai secret di command line ditolakTerpenuhi
6.2 Algoritma yang disetujui, tanpa kripto buatan sendiriAES-256-GCM (setiap nilai terikat pada namanya), scrypt N=2^17 r=8 p=1, crypto/rand, key Ed25519, SSH dan TLS dari GoTerpenuhi
6.4.2 Materi key terlindungiSemua yang disimpan komando disegel dalam satu file (store.db, AES-256-GCM per record). Vault baru menyimpan key-nya di keychain OS (keychain macOS, Secret Service Linux, Credential Manager Windows), dibaca ulang sebelum dianggap berhasil; mode passphrase tidak menyimpan key di disk; bila keduanya tidak ada, dipakai file key yang hanya bisa dibaca Anda (mode 0600 di folder 0700, atau daftar akses khusus pemilik di Windows); komando secret keychain memindahkan key dari file itu ke keychainTerpenuhi dengan keychain atau passphrase. Sebagian terpenuhi tanpa keychain: file key berada di samping vault (doctor memberi peringatan)
4.1.3, 4.3.1 Hak akses minimum, antarmuka administrasikomando ssh-gate membatasi SSH key perangkat lain hanya untuk komando: tanpa shell atau forwarding, aturan agen, tidak ada yang ditulis di komputer komando (juga tidak lewat file sqlite, dan tidak ada apa pun, bahkan pembacaan, di target pada alamat loopback), key --read-only hanya menjalankan pembacaan, dan hanya yang tetap berada di server dan conn yang terdaftar kecuali barisnya memakai --network, setiap perintah diaudit dengan nama keyTerpenuhi. Tugas Anda: tambahkan key ponsel dengan komando ssh-gate line
7.1 Log mencatat siapa, apa, di mana, hasil, tanpa secretSetiap tindakan: waktu, aktor, agen AI, persetujuan, host, perintah; diuji tidak memuat kata sandiTerpenuhi
7.3 Log terlindung dari perubahanAudit log disegel di store.db, rantai hash yang diperiksa komando audit verify; dengan key di keychain, salinan lama store yang dikembalikan menghentikan setiap perintah (STORE_OLD_COPY); dan setiap record bisa dikirim ke server log dengan audit_syslogTerpenuhi dengan audit_syslog. Sebagian terpenuhi tanpanya: user yang sama bisa membangun ulang rantai atau memotong ujungnya
8.3 Data sensitif tidak ditampilkan kepada yang tidak berhak melihatnyaNilai vault disembunyikan untuk semua orang; kata sandi, key, dan token disembunyikan untuk agen AI yang dikenali komandoSebagian terpenuhi: penyamaran bersifat upaya terbaik, dan nama yang tidak lazim bisa lolos
9.1, 9.2 Koneksi terenkripsi dan server diperiksaHost key SSH (berhenti bila tidak cocok; key pertama ditampilkan dengan fingerprint-nya); SSH meminta dulu pertukaran key hybrid pasca-kuantum mlkem768x25519-sha256 (default OpenSSH 10, juga ada di OpenSSH 9.9), baru curve25519; TLS 1.2+ untuk Redis, Kubernetes, FTPS, HashiCorp Vault, dan klien VPN bawaan; WinRM lewat HTTPS dengan sertifikat diperiksa (HTTP polos hanya dengan ?tls=off); share SMB menandatangani setiap pesan dan dienkripsi saat server memintanya; IKEv1 tanpa 3DES atau grup DH di bawah 14 secara default; tanpa PAP secara default; FTP dan WebDAV polos butuh ?insecure=1, begitu juga conn Redis dan memcached polos yang baru lewat jaringanSebagian terpenuhi: conn Postgres dan MySQL baru lewat jaringan memeriksa sertifikat kecuali URL menyatakan lain; conn yang sudah tersimpan mengikuti URL-nya, dan doctor memperingatkan yang tanpa TLS terverifikasi serta mencetak perbaikannya. --legacy-crypto (3DES, grup DH 2 dan 5) dan --allow-pap menyalakan kembali opsi lemah itu untuk satu VPN, dengan jawaban ya dari seseorang
12.3 File: tanpa path traversalDownload folder menolak path server yang mengarah ke luar targetTerpenuhi
14.2 Dependensi diketahui dan selalu diperbaruiGo module, govulncheck di CI, DependabotTerpenuhi

Batasan

Yang tidak dicakup komando:

  • Agen AI adalah user Anda sendiri. komando menghentikan kesalahan dan instruksi yang disisipkan; komando tidak bisa menghentikan program yang berjalan sebagai Anda dan berniat jahat. Isolasi sungguhan butuh sandbox OS atau akun user terpisah untuk agen.
  • Key vault tidak berada di hardware key (YubiKey, TPM); keychain OS adalah tempat terkuat untuk komando menyimpannya.
  • Jendela persetujuan hanya satu klik, kecuali kode persetujuan dinyalakan (komando config approval-code): dengan itu jendela juga butuh kode 6 digit dari aplikasi authenticator.
  • Guard hanya berjalan di tempat harness agen memintanya. komando guide install memasangnya untuk Claude Code, Cursor, Gemini CLI (v0.26+), dan Codex (setujui sekali di /hooks). Guard diuji dengan input hook yang didokumentasikan masing-masing. Agen tanpa hook hanya mendapat jendela persetujuan dan penyamaran, dan itu hanya bila komando mengenalinya: Claude Code, Codex, Cursor, Gemini CLI, atau agen apa pun dengan KOMANDO_AGENT=1.
