Hasil dan error

Cara komando menjawab, arti exit code, cara memperbaiki error yang umum, dan cara melihat apa yang masih berjalan.

Di halaman ini

  • Membaca hasil
  • Exit code
  • Apa yang masih berjalan, dan di mana saya?
  • Apakah script saya tetap berfungsi?
  • Referensi: komando schema
  • Pemecahan masalah

Membaca hasil

komando exec web1 -- uptime              # teks yang mudah dibaca di terminal
komando exec web1 -o json -- uptime      # satu objek JSON (yang diterima agen)
komando status                           # VPN, login, tunnel, dan job yang masih berjalan
komando doctor                           # periksa pengaturan lokal

Di terminal Anda mendapat teks yang mudah dibaca. Saat program lain (seperti agen AI atau script) menjalankan komando lewat pipe, hasilnya satu objek JSON. Paksa salah satunya dengan -o text atau -o json, atau atur KOMANDO_OUTPUT. --pretty memberi indentasi pada JSON.

Agen atau script yang hanya ingin membaca apa yang berjalan di server juga bisa meminta teks: komando exec web1 --read-only -o text -- cat /etc/hosts mencetak output server apa adanya. Exit code komando tetap miliknya sendiri (5 bila perintah keluar dengan kode bukan nol), bukan milik perintah itu. Dengan beberapa server, tiap server mendapat satu blok berjudul === web1 [ok, exit 0] (atau [failed: exit 1], [skipped] ...). Pakai JSON bila Anda butuh exit code atau error tiap server sebagai data.

Teks dari server, database, dan pod lebih dulu dibuat aman untuk terminal Anda: warna tetap ada, tetapi escape sequence yang memindahkan kursor, mengatur judul jendela, atau menulis ke clipboard, teks tersembunyi (ESC[8m), karakter kontrol lain, dan bidi override (U+202E, yang menampilkan teks dalam urutan berbeda dari urutan sebenarnya) dicetak sebagai \e, \xNN, dan ‮. Carriage return tetap ada, sehingga progress bar bekerja, kecuali pada baris yang diawali nama server atau pod ([web1] ...): di sana ia tampil sebagai \r, sehingga server tidak bisa mencetak menimpa nama itu. Di JSON, data menyimpan byte apa adanya, di-escape dengan cara JSON: isinya adalah file, baris, atau output itu sendiri. Kata-kata yang ditulis komando tentang sebuah hasil juga dibuat aman di sana, karena siapa pun yang membaca JSON itu menampilkannya kepada seseorang: error.message, error.hint, dan error.suggestion (juga di objek error pada sebuah hasil, satu per server), meta.warnings, meta.skipped, meta.would_be_blocked, serta name dan detail dari pemeriksaan doctor. Karakter format yang tak terlihat (zero-width space, word joiner, tag character) juga tampil sebagai \uNNNN di sana. Ini untuk tampilan: teksnya berubah, jadi bandingkan kode, bukan pesan.

{
  "ok": false,
  "command": "exec",
  "data": {
    "command": "uptime",
    "results": [ { "host": "web1", "ok": false, "exit_code": 3, "stdout": "", "stderr": "…" } ],
    "summary": { "total": 1, "ok": 0, "failed": 1, "failed_hosts": ["web1"] }
  },
  "error": { "code": "FAILED", "message": "server web1 failed", "hint": "…" },
  "meta": { "contract": 2, "version": "…", "duration_ms": 211 }
}
FieldArtinya
oktrue hanya bila semuanya berhasil
commandID perintah: kata-katanya digabung dengan titik (exec, db.query, fs.list, secret.show). komando audit --command menerima ID yang sama
datahasilnya. Perintah yang berjalan di banyak server memakai data.results[] (satu per server) dan data.summary. Setiap hasil menyebut servernya di host (exec, facts, test, cp ...)
error{code, message, hint} bila ok bernilai false. data masih bisa ada saat server gagal (PARTIAL_FAILURE)
error.suggestionuntuk salah ketik: nama yang menurut komando Anda maksudkan (perintah, server, flag). Hint-nya lalu berisi seluruh baris perintah dengan nama itu di tempatnya. Kata dari tool lain (ps, kubectl, psql) mendapat perintah komando yang mengerjakan tugas itu. Tidak ada bila tidak relevan
error.hintselalu menyebut apa yang dicoba berikutnya. Kebanyakan kode punya hint sendiri; bila ada yang tidak punya, komando memasukkan hint umum untuk exit code-nya (misalnya, exit 7 menyarankan --timeout atau komando job start)
nullkomando tidak bisa mencari tahu (misalnya facts tanpa hak untuk membaca sesuatu). Tidak pernah menggantikan 0 atau false
metacontract, version, duration_ms; dry_run dan would_be_blocked pada dry run, would_need (setiap flag persetujuan yang dibutuhkan eksekusi sungguhan) dan not_simulated (langkah yang tidak bisa dicoba dry run tanpa benar-benar menjalankannya, seperti pernyataan DDL MySQL atau VACUUM milik sqlite); skipped bila target memilih hal yang tidak bisa dipakai perintah ini, dengan alasannya (juga saat perintah itu lalu gagal); host_keys_pinned bila perintah mempercayai host key SSH sebuah server untuk pertama kalinya (host, address, key_type, fingerprint), untuk dibandingkan oleh seseorang dengan milik server itu sendiri; truncated bila daftar berhenti di --limit dan masih ada lagi (--limit 0 menampilkan semua)

6diblokir demi keamananPOLICY_BLOCKED, PROTECTED_TARGET, WRITE_REQUIRES_FLAG, DECLINED

Saat beberapa server gagal, exit code-nya adalah yang terburuk. Referensi lengkap yang bisa dibaca mesin adalah komando schema; komando help exit-codes dan komando help output mencetak versi singkatnya di terminal.

Apa yang masih berjalan, dan di mana saya?

komando status mencantumkan VPN, login, tunnel, dan job yang masih berjalan (lihat Melihat apa yang masih berjalan), dan baris yang dicetak komando sebelum shell dan perintah serupa ada di Di mana saya?.

Apakah script saya tetap berfungsi?

Setiap jawaban JSON punya meta.contract. Di dalam satu contract, komando hanya menambah field, kode error, dan exit code ke envelope JSON; komando tidak pernah mengganti nama atau menghapusnya. Nama perintah dan flag bukan bagian dari contract: komando sementara ini dipakai secara internal, jadi perintah atau flag yang diganti namanya tidak menyimpan nama lama, dan changelog mencantumkan setiap perubahan. Jika envelope suatu hari harus berubah, meta.contract naik dan changelog menjelaskan apa yang berubah.

Referensi: komando schema

komando schema exec                      # setiap flag exec, bisa dibaca mesin
komando schema secret.show               # sebuah perintah menurut ID-nya, seperti nama di JSON
komando schema                           # juga setiap exit code dan kode error

Setiap perintah di komando schema punya kind (read, change, atau depends) dan daftar confirm dari tabel aturan komando: lebih dulu tingkat yang selalu dimilikinya, lalu setiap tingkat yang hanya kadang dicapainya, dengan flag yang ditambahkan agen atau script dan kapan, misalnya [{"tier":"change"},{"tier":"dangerous","flag":"--allow-dangerous","when":"with --remove-home"}]. Tingkatnya adalah read, change, dangerous (--allow-dangerous), safety (--yes), dan person (tanpa flag: seseorang di terminal yang menjalankannya). Perubahan di server atau conn yang dilindungi juga butuh jawaban ya; targetnya yang menentukan, jadi tidak dicantumkan. Lihat Apa yang butuh jawaban ya.

Perintah add juga mencantumkan jenis yang diterimanya, di add_kinds, sehingga program bisa menyusun formulir add dari sana. komando schema vpn add memberi setiap jenis VPN id, display_name, family (portal, config_file, server_psk, auth_key, system, atau proxy), aliases, flag yang dibutuhkan (required, dan one_of: kelompok yang cukup satu flag-nya), flag yang boleh dipakai (optional), flag_notes, dan opens_browser: apakah vpn up membuka browser untuk login (browser_note menyebut kapan). komando schema conn add (dan db add, cache add, queue add, storage add, cluster add, registry add untuk jenisnya masing-masing) memberi setiap jenis conn id, display_name, family, url_schemes, url_example, default_port, dan daftar flag yang sama. Semuanya berasal dari tabel yang sama dengan komando vpn add --help dan komando conn kinds.

Pemecahan masalah

Tabel di bawah berisi error yang paling sering ditemui. Setiap kode yang diberikan komando, dengan exit code-nya, contoh pesan, dan langkah berikutnya yang lazim, ada di Kode error, dan di komando schema pada error_codes:

komando schema -o json | python3 -c 'import json,sys; [print(c["code"], c["exit"], c.get("example","")) for c in json.load(sys.stdin)["data"]["error_codes"]]'

Untuk penghentian demi keamanan (exit 6): di terminal Anda komando bertanya dulu; agen AI atau script menambahkan --yes (atau --allow-dangerous) setelah seseorang setuju. Lihat Keamanan.

komando doctor memeriksa pengaturan lokal Anda, inventaris, dan keamanannya.

Dalam -o json, pemeriksaan doctor yang bisa diperbaiki oleh satu perintah komando punya fix: kata-kata yang dijalankan, sebagai daftar (["komando", "conn", "edit", "db2", "--protected"]). detail menyatakan hal yang sama dalam prosa. Program yang menawarkan perbaikan itu membaca fix dan tidak pernah mengambil perintah dari detail. Sebuah pemeriksaan punya fix hanya bila satu perintah memperbaikinya apa pun keadaan lainnya, dan perintah itu tidak menanyakan apa pun: pemeriksaan dengan beberapa jalan keluar, yang butuh nilai atau passphrase dari Anda, yang hanya bisa Anda nilai sendiri (dua conn yang tampak sama), atau nama yang bisa terbaca sebagai flag, tidak punya fix.
